# 制作清单与校验

## 交付给谁

场记和摄影需要按拍摄条件组织的机位表。演员需要动作、出入位、眼线和提示词。剪辑需要观看顺序、采用长度、声音切点、备选覆盖和镜头 ID。AI 或合成人员需要静帧、动态说明、素材用途和接点状态。小场次可用两张表。多场戏或混合制作时，镜头 ID 贯通所有表和文件名。

正式交接可以保留以下记录，按需求取舍。

| 记录 | 必要信息 |
| --- | --- |
| 叙事节拍 | 关键事件、可见或可听证据、观众察觉时点、必需与可选 |
| 场地图或走位表 | 地标、人物起止点、当前轴线、相机朝向、主光、进出画、待现场确认 |
| 主剪辑 | 成片起止时间、镜头 ID、动作与切点、声音及连续性 |
| 拍摄单 | 机位组、优先级、需拍表演范围、灯光与收声、复位、已知耗时窗口 |
| 最低保底剪辑 | 实际可拿到的镜头、观看顺序、每处关键信息和如何转接声轨 |
| 混剪与调试 | 实拍/AI/合成路线、参考素材、镜头接点、验收帧、失败时的可剪替代 |

## JSON 清单

用户需要可机器读取、表格导入或重复校验时，参照 [混合制作清单](examples/after-hours.plan.json)。镜头表可继续用 Markdown 或项目已有格式。以下清单专用于提供采用段和关联的结构化副本。

- `schema_version` 为 `1`。`beats` 是节拍数组，含 `id`、可选 `description` 和 `required`。`required` 默认真。
- `setups` 按现场拍摄顺序排列。每项至少有 `id`，可加 `description`、灯位和复位备注。纯 AI 清单可省略或留空。
- `shots` 每项含 `id` 以及 `method`。`live` 和 `composite` 的 `setup` 引用一个主要实拍机位。纯 `ai` 留空或省略 `setup`。合成需要的其他底片和参考可另记到生产备注。
- `main` 是采用顺序，含 `target_ms` 和 `cuts`。`fallback` 可选，结构相同，可有自己的预定时长。两条时间线各自从 `0` 开始。需要限定到某种制作方式时，用 `allowed_methods` 声明，例如全靠实拍的保底用 `["live"]`，校验器会发现混入的 AI 或合成镜头。
- 每个 `cut` 有 `id`、`shot`、`in_ms`、`out_ms` 和 `covers`。`in_ms`、`out_ms` 是成片时间，区间左闭右开。`covers` 只填这个采用段能表达的节拍。多个采用段可以引用同一个拍摄镜头。素材时间、额外留量和声音轨道时间可通过项目记录补充。
- 已选具体素材时，可在采用段写 `source`，它包含 `take`、`in_ms`、`out_ms`，时间从这条素材的开头计算。知道真实素材长度时加 `available_ms`。同一条素材可用于两版剪辑和多个采用段，各自列实际取段。确有变速或定格时标 `retimed: true`。速度和处理方式写在剪辑备注里。
- ID 由字母或数字开头，可包含点、下划线、连字符。`covers` 引用 `beats`。同一安装包可以处理多种镜头表，仅这个可选格式参与脚本检查。

```bash
python3 scripts/check_plan.py references/examples/after-hours.plan.json
python3 scripts/check_plan.py /path/to/plan.json --csv /path/to/timeline.csv
```

脚本检查类型、重复 ID、镜头/机位/节拍引用、剪辑空隙或重叠、总时长、必需节拍、已声明的素材区间和原速片段长度。CSV 含主剪辑及保底采用段，可导入表格。脚本使用 Python 3 标准库，目标 CSV 需为新路径。它验证清单声明的覆盖关系，台词、空间、焦点和表演能否成立请按 [连续性与剪辑验收](continuity-and-edit.md) 检查。

想看完整决策链，读 [三人咖啡馆混合制作示例](examples/after-hours.md)。
